# Как найти смысл данных в вашем проекте - 1

В данном материал говорилось о том, как важно выстраивать правильную модель для данных, конкретно рассматривался случай с иммутабельностью и мутабельностью данных в проектируемом отношении, рассматривали отношения (квест и локация). Пришел к определенному выводу о том, что важно в выстроенном отношении не позволять появляться сторонним эффектам (например изменение внутреннего состояния). Важно уметь получать данные и изменять объект путем создания нового и копирования в него данных старого, тем самым мы избавляемся от side effects.

Также важно учитывать - что в программе будет использоваться чаще, какие данные будут запрашиваться чаще, и оптимизировать модель данных таким образом, чтобы те данные, которые нужны чаще - мы получали быстрее. Этому способствует **денормализация** данных - процесс в котором наши данные будут находится рядом друг с другом в определенном отношении.

## Примеры

- **Строительные тендеры -> множество компаний претендентов** - здесь во время обработки тендера мы постоянно обрабатываем компании, чтобы определить победителя и удобнее будет будет их держать близко к определенному тендеру
- **Рейс самолета -> множество самых критичных данных по пассажиру** - для быстрого доступа к данным
- **Сторис в приложении -> количество лайков, самый залайканный комментарий** - для быстроты получения данных
- **Платежный документ -> сумма и данные по платежному документу** - для удобства работы с важными данными без лишней подгрузки
